# 项目 AGENTS.md 中的 Codinator 调度约定

本文从 AlphaLab 的 `AGENTS.md` 提取跨项目可复用的执行约定。使用 Codinator 的项目可复制下文，再填写本项目的预算、路径、依赖和业务验收条件。本文约束主 Codex、实施者和审查者的行为；不新增 manifest 字段，也不表示控制器会自动判断任务进展或业务正确性。

接口以当前安装版本的 [README](../README_CN.md)、[Git 协议](git-checkpoints.md)、[交接协议](codex-interface.md)及实际发布契约为准。下面的新任务约定使用 manifest v2、`handoff_protocol: 1` 和原生 Pi 输出观察模式。旧任务继续遵守其冻结契约。

## 使用前需要确定的项目参数

- 确定 Codinator 可执行文件、现有服务和同一个 `--state-dir`。不要复制其他项目的状态目录或任务 ID。
- 确定普通 Git checkout、任务分支、完整基线 SHA、依赖和只读输入版本。
- 确定允许修改的路径、临时与持久输出路径、精确检查命令及各项超时。
- 确定阶段总墙钟预算、累计实施派发次数、单进程硬上限及观察间隔。区分研究／计算资源限制与控制器时间限制。
- 确定业务验收条件、适用的独立审查门槛，以及父任务还需验证的组合行为。

AlphaLab 采用30分钟观察间隔和90分钟单进程硬上限；其16小时／4次阶段实施派发是项目授权，不是 Codinator 的通用默认预算。其他项目必须采用自己的已授权额度。复制以下约定不构成新增预算、权限、合并或发布授权。

## 可复制到项目 AGENTS.md 的约定

```markdown
## Codinator 任务调度

### 职责与授权

- 主 Codex 负责需求、任务划分、冻结 handoff、预检、发布、进度判断、纠偏和结果解释。Pi + Bonsai 负责实施、项目命令、测试及任务分支的本地 Git 提交。独立 Codex 负责核验候选和原始证据，并裁决验收。
- Codinator 只传递 handoff、summary、guidance 和 review，调度进程，记录状态与证据，管理预算并串行化写入者。它不实施业务任务，不运行项目测试，不调用 Git，不生成源码快照，不清理缓存，不合并或推送。
- 在已有授权内持续推进正常实施、检查和返工。需要扩大范围、预算或外部权限时，先核对已有授权；仅对超出授权的部分请求决定。任务完成不自动授权合并、推送、共享数据发布、部署或实盘操作。
- 保持契约指定及当前 Codinator 支持的模型配置。不得静默更换模型或启动竞争的实施者。不使用无沙箱回退，也不宣称尚未获得的目录权限。

### 任务划分与发布预检

- 只拆解已确认的需求。按职责、接口和耦合关系划分；一个工作包尽量只有一个可验收目标。实现、针对性测试和必要报告可在同一包交付。不要加入额外功能、通用化设计或非必要重构。
- 每个任务写明对应需求、目标、修改边界、依赖、交付物、验收条件、实施者、验收者及前后交接。关键行为有歧义时先澄清；技术不确定时先做有界小实验，不用继续拆分代替设计决策。
- 主 Codex 发布前核对真实接口、输入合法状态与消费者处理，以及依赖版本、数据可读范围、输出权限和交付机制。预检只解决当前接线所需的未知；不能把接口猜测或未解决的环境问题交给 Pi。
- 固定仓外输入的实际版本、所用 manifest／receipt 和必要内容哈希。会移动的指针不是唯一输入身份。清单漂移时核对本任务所选文件和语义的实际影响；缺少冻结能力时先明确有界依赖改动。
- 使用当前支持的 manifest v2 和 handoff_protocol: 1。发布前提交只读 handoff、固定忽略规则及基线；填写 workspace、git.branch、完整 git.base_commit、精确 allowed_paths、checks[].argv、各项 timeout_seconds 和已授权预算。handoff 不得列入 allowed_paths。
- 授权、依赖、路径权限及 Git 预检完成后才启动执行预算。研究试验、数据读取与计算资源上限写入 handoff，不虚构控制器字段。

### Handoff 与启动入口

- Handoff 开头给出目标、最小阅读入口、执行顺序、首个可验证行为及检查命令。使用已核实的函数、输入样例和准确路径。保留完整约束和验收条件；不要要求 Pi 通读历史材料。
- 明确首个行为的预期结果、实际命令、退出码及原始证据要求，并给出有针对性的边界反例。涉及时间、单位、结算或外部接口时，逐路径写明合法输入、最小时间线及允许、禁止或明确失败的行为。
- 主 Codex 确保启动提示提供本 attempt 的实际绑定交付命令和 evidence packet 模板。Pi 在编辑前读取当前 delivery contract；入口支持 --help 时先核对调用方式。入口失败时保存错误并求助，不猜包名或研究控制器内部实现来寻找提交方式。
- Handoff 写明正常交付、求助、阻塞及停止的收尾顺序和最小证据。未执行检查如实使用 not_run 和 exit_code: null；这不豁免验收必需检查。不能等到全部测试通过才报告阻塞。
- Pi 阅读只解决当前具体未知。扩大阅读前说明缺少的信息、目标文件／函数和获得答案后的动作。原输出仍可用且文件未变时，不重复整篇读取；不以了解整体架构为由跨仓库探索，也不设置机械读取次数上限妨碍必要核验。

### Git、检查与证据

- 每个任务使用独立 Git 分支，默认在同一普通 checkout 中串行执行；当前协议不支持 linked worktree。开始或切换前确认干净状态，并记录完整 SHA、分支及所有 refs。保存无关未提交工作，不强制切换或 reset 丢弃现场。
- 同一 checkout 只允许一个写入者。主会话不得同时编辑自动任务的工作目录。检查和独立验收期间冻结候选，不切换分支或修改源码。控制器锁不能阻止同一用户直接改文件，仍须遵守此约定。
- Pi／Codex 在关键节点及检查前核对范围，提交全部应交付文件，记录完整 SHA。已授权任务专属分支内的本地检查点无需逐次确认；本地提交不表示验收或推送授权。Pi 的 Git 写入仅用于任务本地提交，不改分支、配置、hooks、忽略规则或历史。
- 检查绑定最终候选 SHA。源码或测试改变后重新提交，并重跑受影响检查；最终交付及独立验收须满足当前契约的全部必需检查。不能把旧 SHA 的结果直接用于新候选。
- 保存每条实际命令的顺序、退出码和原始输出。按契约保留执行时间。使用检查进程的真实退出码，不把日志裁剪管道的退出码当成测试结果。不把事后重建记录写成当时生成的原始证据。
- 源码版本和恢复由标准 Git 管理。缓存按冻结的 .gitignore 处理；仓外数据、模型及实验产物按其契约记录版本和必要哈希。控制器不代为提交，不另建源码快照或 blob 系统。
- 临时输出使用当前沙箱允许的路径；当前审查契约仅允许 /tmp 写入。持久产物放在预检确认可写的声明路径。原始控制器运行证据留在状态目录；不要复制认证信息或私密会话到项目仓库。

### 输出观察与纠偏

- 新原生 Pi 包启用 checkpoint_mode="observe"、checkpoint_seconds=1800、attempt_seconds=5400。通过 checkpoint_outputs 声明有实际行为含义的工作区相对文件路径；文件由任务产生，控制器不发现或创建进度输出。
- observe 模式不能同时设置 checkpoint_format、first_checkpoint 或 counterexamples。首个行为和反例写入 handoff。此模式不支持 implementation="external"。
- 控制器在启动时及每30分钟采集声明文件的有界样本和工具事件。主 Codex 根据实际命令、退出码和原始结果判断行为是否完成；阅读、设计、日志活跃、测试数量或格式合规不能代替验证。
- 观察不发送软检查请求，不要求 Pi 定期回应，也不设置5分钟回应超时。缺失、部分输出或沉默本身不自动停止任务。正常观察继续同一 attempt，不在每个检查点重启；完成、求助和停止仍提交完整 summary 及适用 evidence。
- 主 Codex 可在30分钟之前根据行为证据纠偏。先区分上下文缺失、契约含糊、接口／环境问题、测试设计错误和执行漂移。反复阅读却未解决新未知时，不盲目增加预算或重复派发，也不假设控制器能自动识别阅读漂移。
- 需要纠偏时使用原生 pause，核验进程及工具确实停止，再由主 Codex 保存 Git 现场并提供明确指导。恢复前验证新的交接可执行，保留剩余额度。不要在活动进程旁边修改工作目录或已发布 handoff。
- 相同假设连续失败两次、契约冲突或没有可验证进展时，Pi 通过绑定工具提交 needs_guidance 或 blocked 后停止。技术求助使用 help 模板并提供干净、已提交的部分候选及正常 evidence；外部权限问题或无法协调的候选使用 blocked。观察器不自动调用指导模型；协议 1 的有效求助在进程／协议确认结束后可由控制器路由至独立指导者。
- 明确指导后仍遗漏关键约束或重复探索时，评估主 Codex 接管。指导者或实施者不得兼任该改动的独立验收者。旧报告模式任务继续遵守原冻结的回应、纠偏和停止规则。

### 预算、恢复与上下文

- 按项目授权发布阶段总墙钟和累计实施派发次数。同阶段新工作包使用相同 stage={id,max_seconds,max_rounds}；各包、失败、返工及接管不得重置额度。实施、检查、指导和独立验收共享固定时间窗口，已开始的等待和暂停仍计时。
- 每次实际实施派发消耗实施轮次，包括启动失败、指导后的继续及中断后的普通恢复。指导和 review 消耗时间，不增加实施轮次；不要把 attempt 数直接当成实施派发次数。单任务额度和固定绝对截止仍约束执行。
- 当前共享 stage 限于同一 state root、同一 workspace 和完全相同的阶段授权。跨仓库、跨状态目录或已有未分组历史须依据原始记录人工核算；不能借新 ID、新 stage 或新默认值冲销历史消耗。
- 普通恢复前核对原因、进程、分支、候选 SHA、阶段证据及剩余预算。返工沿用任务分支，保留旧 attempt、契约、原始证据和裁决。范围或基线需要改变时准备明确后继契约，不改写已发布 handoff。不要重放执行结果不确定的操作，也不直接修改数据库推进状态。
- 跨 attempt、暂停恢复或更换实施者时，提供简短续执行摘要：候选完整 SHA、已验证事实与原始证据、已知反例、已排除路径及适用范围、剩余问题、未执行或结果不确定的操作、下一条操作、累计时间和轮次。主 Codex核对原始记录，区分实施者自报与独立结论。
- 续执行摘要写入新 handoff 的 Required inputs 或当前支持的反馈入口，不另造字段，也不替代冻结契约或完整 summary。当前实现每个 attempt 启动独立 Pi 会话，不自动恢复旧对话。将来使用会话恢复前须核实实际能力、旧进程停止和上下文一致；旧会话不提供新权限或有效交付绑定。
- review-only 只用于契约支持的中断审查，复用完整原始交付和候选，不增加实施轮次；独立 Codex仍核验 Git 并执行必需检查。不能用它绕过已形成的 verdict，或改写已选定证据。
- 使用已核实的 submit 发布、status 读取状态，所有命令指向实际服务的同一 --state-dir。已有后台 serve 时不启动竞争控制器。升级前确认旧模型进程停止；升级不自动恢复 blocked／paused 任务。v1 任务仅保留历史查询，后继任务核算原剩余额度。

### 主 Codex 接管

- 已授权的主 Codex 实施使用 implementation="external" 的显式交接协议。先冻结 handoff／基线并完成预检，再 begin-external 记录起点、作者和截止。宿主 Codex 自己执行 Git 和检查，保存真实初始／最终 refs、命令及检查原始日志，按当前绑定入口交付并 finish-external。
- 宿主 Codex 负责自身硬停和检查点；控制器不能终止宿主会话。超时不证明工具停止。确认工具停止后，通过完整阻塞小结及 stop-external 释放占用。不要对活动 external 实施假设普通 pause／cancel 会代为停止宿主工具。
- 接管仍计入阶段预算与实施次数，并进入非作者独立验收。不得伪造 Pi 完成、导入手写 accepted 或由作者自验收。

### 文档与验收

- 使用发布时冻结的 handoff、summary、help、review、guidance 模板和绑定身份。Handoff 包含任务描述、范围、输入、交付物、验收条件及交接规则；summary 区分完成、未完成、尝试、证据、偏差和下一步；review 声明 accepted／needs_changes／blocked，并提供依据和适用的返工提示。
- 借鉴 ASD-STE100 的清晰表达原则，不要求完整词表合规。使用短而完整的句子；每条指令明确对象、条件和动作。同一概念使用同一术语。区分要求与建议、事实与假设、已验证与未验证，并标明证据版本和范围。简化不得改变否定、条件、例外、数量边界或不确定性；歧义先标出再澄清。
- 区分 RPC 请求已接收、进程退出、protocol_completed、有效交付和任务 accepted。超时、请求回执或日志活跃不能证明工具停止或任务完成。原始终态不确定时保存现场，不重放未知操作。
- 只通过本 attempt 绑定入口提交真实 SHA、检查结果和证据。不猜身份、不手写控制器完成状态、不修改验收阈值或原契约来使任务通过。结构合规或提交回执不表示内容真实、任务完成或独立验收。
- 独立 Codex在只读源码、Git 和原始证据上核验实际 HEAD、分支、干净状态、祖先关系、逐提交修改范围、冻结契约、提交在检查之前及原始日志，并复跑当前契约必需检查。只有其绑定精确候选 SHA 的 verdict 能在 Codinator 中接受交付；Pi 自报不能替代独立结论。
- 审查只依据原契约提出实质问题，不在每轮增加新验收条件。返工说明问题位置、原要求依据、具体修正及复验方式；格式通过或测试数量不能代替行为与产物口径核对。
- 复用未改变部分的既有独立结论，明确适用 SHA、输入版本和范围。检查范围按修改影响、当前契约和父任务要求选择；无新变化或未决风险时，不重复已覆盖的数据扫描或另加无关检查。这不免除当前发布契约的必需检查。
- 父任务验收组合行为和跨任务约束，不能只凭所有子任务通过。区分合成接口检查、真实接线、真实运行及业务／研究达标；正确且证据完整的负结果可以是成功技术交付。accepted 不自动证明业务收益、安全上线或策略达标。
- 本项目普通文档和低影响改动可按本项目规则自审；若任务进入 Codinator 验收流程，仍遵守该流程的独立 verdict。已完成且满足实质风险要求的独立审查可复用，不另造重复审查门槛。
```

## 接口与历史差异

- [输出观察示例](../examples/observation-task.json)展示当前字段。示例中的路径、基线 SHA、检查和预算必须替换为真实授权值。`checkpoint_outputs` 可省略，最多16个不同的相对文件路径；不能使用目录、通配符、受保护路径或符号链接穿越。有界采样可能缺失或不完整，不能视为完整检查日志。
- 未设置 `checkpoint_mode` 的旧任务保留报告模式。其5分钟回应要求不适用于 observe；5分钟交付格式修复也不是 observe 的回应超时。不要用新规则追溯修改旧任务。
- 主 Codex 的外部实施使用 [external 协议](../README.md#s03-harness-improvements-opt-in-for-new-tasks)。原始日志清单和绑定命令以该 attempt 的实际 instructions／contract 为准，不能沿用旧 attempt 的入口。观察模式与 external 不能混用。
- 同阶段额度与固定截止由发布记录约束。增加某个 task 的额度不能延长冻结 stage；需要补充授权时保留旧账目，通过当前支持的后继契约或恢复入口承载新增额度，不能手改旧记录或隐式重置。
