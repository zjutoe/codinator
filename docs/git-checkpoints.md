# Git 分支与源码检查点

新任务使用 `version: 2`。Git 保存源码历史、差异和检查点；Codinator 保存任务状态、进程、预算、交付、检查日志与独立审查结论。无需另建 worktree，同一 Git 仓库串行执行。控制器不自动切换分支、reset、stash、合并或推送。

## 发布

1. 创建并检出任务分支，妥善保存原有工作。
2. 将 handoff、验收契约、`.gitignore` 及实施基线提交到 Git。工作目录须干净，不能留待任务代为处理的暂存或未跟踪源码。
3. 用 `git rev-parse HEAD` 获取完整 SHA；在 [manifest 示例](../examples/task.json) 中填写 `git.branch`、`git.base_commit`、工作目录、允许修改路径、检查命令和预算，然后 `codinator submit`。

```json
{
  "version": 2,
  "git": {
    "branch": "mf-001-S02-WP02",
    "base_commit": "8c05779165ecb0030643e8d09c1fdfd2ecf43e52"
  }
}
```

这只是版本字段示例，不是可直接发布的完整任务。提交意味着授权控制器为该任务在指定分支生成本地检查点提交。检查点不代表验收通过，不授予合并、推送或新预算。发布、派发和恢复都会核对实际分支与记录的提交；排队期间自行切分支或修改源码将导致拒绝派发。

Git 不允许 `mf-001` 与 `mf-001/S02/WP02` 两个分支名共存。可以保留 `mf-001` 并使用 `mf-001-S02-WP02`；分支继承关系由创建时的 commit 决定，与名称是否含 `/` 无关。

## 实施、提交与验收

Pi 的 `.git` 仍只读，只修改允许路径。v2 实施阶段先编辑和检查代码文本，将测试标记为尚未执行，提交绑定交付后停止；控制器核验进程退出与修改范围，生成 Git 提交，再运行 manifest 中的检查。独立 Codex 审查同一个候选提交、原始要求、实现差异和控制器日志。

`before.json`、`implementation.json`、`submission.json` 保存简短 Git 身份：`kind`、`branch`、完整 `commit` 和 `tree`。v2 的 `submission_digest` 与状态中的 `expected_digest` 均表示完整 commit SHA。不同 SHA 即使 tree 相同，也不能替换已检查提交。

`status.git` 显示任务分支、发布基线与最新检查点提交。源码变更留在任务分支，返工在其上继续，不重置历史预算和轮次。控制器与审查不因为 Git 提交存在而宣称任务被接受。

## 忽略规则与边界

缓存通过发布前固定、受 Git 管理的 `.gitignore` 忽略，不复制进控制器源码 blob，不因其新建或变化使候选提交失配，也不由控制器删除。已有 tracked 文件不会因为后来匹配忽略模式而失去检查。

忽略规则在任务内冻结；不得修改 `.gitignore` 或新增会生效的规则来隐藏越界源码。未忽略的越界新文件、删除、重命名和执行位变化仍受 `allowed_paths` 约束。v2 不接受 legacy `excludes`。控制器对不支持的 Git 特性（特殊 index 标志、子模块或内容转换配置等）显式拒绝，不静默绕过。

检查使用 Git 的独立临时 index 核验真实文件内容，避免真实 index 的时间戳缓存掩盖修改。Pi 的文件系统沙箱、只读检查与审查边界保持不变。同一 Git common directory 的锁覆盖发布、运行、恢复和续跑，避免不同状态目录或 worktree 同时写入同一仓库；这不阻止同一用户绕过控制器直接改文件，因此仍须遵守单写入者约定。

## 中断与恢复

确认旧进程退出后，范围内的未完成实现可以生成明确标记为中断的本地检查点；越界工作保留现场并阻塞，不自动提交、删除或回滚。检查或审查期间出现的修改不能当作实施成果接纳。

Git 提交与 SQLite 更新之间使用操作意图和结果记录：`git-submission-intent.json` / `git-submission-result.json`，中断保存使用 `git-interrupted-*`。意图只记录任务、attempt、来源与候选 Git 身份，不保存源码内容。分支更新核对旧 SHA。控制器崩溃后只协调已经记录的 Git 操作，不重复发送 Pi 提示、不猜测未知提交的来源。

普通 `resume` 在既有预算内创建新实施 attempt。仅审查中断时，`resume --review-only` 复用原检查证据及候选 SHA，不增加实施轮次；缺失证据、未协调 verdict、提交或工作目录漂移仍然拒绝。续时须显式授权，原 manifest 和历史预算记录不改写。

## 旧任务与合并

已发布 v1 任务继续使用原文件快照协议，原 blobs、缓存归档、验收和 integration 证据保留。新 `submit` 拒绝 v1；不能直接修改旧任务数据库或 manifest 把它变成 v2。迁移旧成果时，先停止旧执行者、核对来源，将成果提交到新任务分支，再依据原要求和剩余预算准备明确的后继契约。

v2 当前不接受 legacy `integration` 配置。任务验收后保留在任务分支；合并到目标分支属于后续明确授权的 Git 操作，不需要为了提交检查点先建立另一个 worktree。
